# Wrestling Vault development instructions

- Read `docs/development-brief.md` and `README.md` before development.
- The user now authorizes search with suggestions, animated selection, company filtering, downloaded highlighting, synthesized browsing sounds, flat-folder video matching, player skipping, Google search links for missing videos and Netflix Sans when available. This supersedes the prior no-search/no-filter UI restriction.
- The previous design was covers only: a full-width cover browser with click-through to a larger cover. No sidebar, search, filters, sorting, grid toggle, match table, settings or future-feature panels. The user also authorized a top-centre Random button with a book-like cover-flipping animation. Keep it minimal; this user direction supersedes the original brief’s UI requirements.
- The user additionally authorized local video playback: select a video folder on startup and play match videos inside the app. Keep file access in the Electron main process and expose only validated match IDs and opaque media URLs.
- The user authorized replacing the twelve examples with the supplied top 50 catalogue and associated cover images, in supplied rank order. Preserve image provenance, stable IDs for existing matches and local video-folder compatibility.
- The current library replaces the prior top 50 with the user-supplied CAGEMATCH top 100, in supplied rank order. WON star ratings are distinct from CAGEMATCH scores; absent star ratings must remain null/unrated. The user authorized a star-rating dropdown and reverting to the original Vault logo, with existing functionality preserved.
- The user also authorizes mutually exclusive cover/grid layout buttons left of search. Both layouts share selection, filtering, search, random browsing and playback. This supersedes the prior no-grid-toggle restriction.
- The user explicitly approved adding matches from a CAGEMATCH link and a chosen image, review before save, durable local caching, and background sync of catalogue/artwork to the existing GitHub feature branch. Implement that targeted import/sync scope without unrelated collections, analytics or release work.
- The user explicitly authorizes batch imports of supplied CAGEMATCH match URLs with automatic artwork selection and saving, without individual entry confirmation. This supersedes review-before-save for batch imports only. Keep validation, duplicate detection, per-entry failure reporting and actual site rate-limit responses. The user subsequently authorized removing the app-enforced batch cooldown: use sequential in-app browser imports without a fixed delay. Automatic imports must be labelled accordingly.
- The user now explicitly authorizes packaging and deployment as a downloadable Windows desktop app: Windows installer configuration, Windows build checks and publishing the initial GitHub release are in scope. Keep personal data and credentials out of distributable files. No merge to main or unrelated data/analytics phases is authorized.
- Only Phase 1 and the explicitly approved match import/sync extension are authorized. Do not implement SQLite, import pipelines, personal collections, analytics, Windows release CI or subsequent phases until the user explicitly approves that phase. Visual revisions remain Phase 1.
- Use the existing checkout. Cloud tasks are already isolated; do not create a Git worktree unless requested.
- Develop on the appropriate feature branch. Do not merge phase work into `main` without explicit user approval.
- Use npm and preserve the lockfile for reproducible installs. Run meaningful affected tests and `npm run typecheck`; rebuild before production Electron checks.
- Keep Node integration disabled and context isolation/sandboxing enabled. Keep IPC narrow, validate sender and payload, and allow only approved HTTPS reference destinations.
- Never fabricate data verification, historical completeness, Windows testing, or release results. Reference-linked samples are not verified until sources are actually checked.
- Preserve the distinction between original arena art and real match photography. Never scrape or bundle unauthorised photographs.
- Keep secrets, local databases, node_modules, build outputs and test artifacts out of Git.
